## 一句话介绍

`claude-pay` 是一个围绕 **Claude Code 源码泄露事件** 搭建的 TypeScript 开源项目骨架，目标是把一场爆炸级工程事故，沉淀成一个可继续演进的技术项目。

## 事件简述

Anthropic 旗下 AI 编程工具 Claude Code 的部分底层工程代码，曾因发布事故被公开还原并快速传播。外界由此第一次较为完整地看到一套领先 AI Coding Agent 在客户端侧的工程组织方式，包括工作流编排、上下文管理和工具调用结构。

需要强调的是，泄露出来的重点是 **客户端工具代码**，并 **不涉及用户隐私数据，也不包含模型权重本身**。但即便如此，这次事件依然足以让整个技术社区重新审视 AI Agent 产品背后的实现细节与工程门槛。

## 发生原委

原因并不复杂，本质上是一次打包配置失误。

在发布 `@anthropic-ai/claude-code` `2.1.88` 版本时，调试用的 Source Map 文件没有被正确排除，一个体积高达 **59.8MB** 的 `cli.js.map` 被一并发布。由于 Source Map 可以把压缩后的产物映射回原始源码结构，外部开发者很快据此还原出了大量 TypeScript 源代码。

## 这个仓库的定位

这个项目不是单纯为了记录这次事件，而是希望做三件事：

1. 把事件本身讲清楚  
   包括传播链路、触发原因、工程教训和它为什么会在 AI 开发圈引发如此剧烈的关注。

2. 把工程层面的启发沉淀下来  
   例如：Source Map 风险、npm 发布安全、AI Agent 工程架构暴露面、调试产物治理等。

3. 把讨论变成可以继续扩展的代码项目  
   也就是说，它未来可以长成站点、工具、研究 Demo，甚至是一套完整的内容与产品结合体。

## 项目设想

我们对这次泄露出来的代码更感兴趣的，不是“猎奇”，而是它背后体现出来的 **工作流设计能力、工程拆分方式和 Agent 系统搭建思路**。

这个项目的核心设想是：  
**在认真研究和理解 Claude Code 这类产品的工作流与框架设计之后，借鉴其中值得学习的部分，探索 AI 在支付方向上的落地方式。**

我们想做的不是一个简单的“AI 调支付接口”工具，而是一套更完整的 **AI Payment Workflow**：

- 让 AI 能够理解支付任务，而不只是执行单点指令
- 让系统可以把复杂支付流程拆解成多个可验证、可回溯的步骤
- 让用户在更低操作成本下完成从意图到执行的闭环
- 让智能化能力真正服务于风险控制、权限判断和流程编排，而不只是做一个聊天入口

## 我们希望重点解决的问题

### 1. 自动化

支付场景里有大量重复、繁琐、链路长的动作，例如信息校验、订单生成、状态跟踪、异常处理、通知反馈。  
我们希望借鉴成熟 Agent 工作流中的任务拆解与状态流转思路，让 AI 不只是“会说”，而是真的能协助完成整条流程。

### 2. 便捷性

传统支付系统往往功能很多，但使用门槛并不低。  
我们希望把复杂操作收敛成更自然的交互方式，让用户用更少步骤完成支付、查询、确认、对账等任务，把“会用系统”变成“说清需求就能办事”。

### 3. 智能化

真正的智能化不只是对话，而是：

- 理解用户意图
- 识别当前上下文
- 选择合适工具
- 规划执行顺序
- 在必要时向用户追问关键信息

这也是我们研究 Claude Code 工作流的重要原因之一：它给了我们一个很有价值的参照，去理解高质量 AI Agent 在真实工程里是如何组织起来的。

### 4. 安全性

支付永远不是“越自动越好”，而是“在安全前提下尽可能自动化”。

所以这个项目从一开始就会把安全当作核心边界来设计，包括但不限于：

- 权限校验
- 操作确认
- 风险分级
- 日志留痕
- 敏感步骤的人机协同

我们不会把 AI 当成一个可以无限放权的执行体，而是把它放在一个 **可审计、可限制、可中断** 的安全框架中。

### 5. 技能边界

AI 能做什么、不能做什么，必须明确。

在支付场景里，最危险的不是模型“不够聪明”，而是系统对能力边界定义不清。  
因此我们会非常重视：

- 哪些任务 AI 可以自主完成
- 哪些任务只能辅助判断
- 哪些关键动作必须由用户二次确认
- 哪些高风险操作必须被硬性拦截

换句话说，我们不是要做一个“无所不能”的支付 Agent，而是要做一个 **边界清楚、能力可靠、能真正进入真实业务链路的 AI 支付系统**。

## 当前这版项目思路

现阶段，我们把本项目定义为一个持续演进的实验方向：

1. 研究 Claude Code 暴露出的工程结构与工作流思路  
2. 抽象出适合支付场景的 Agent 任务编排模型  
3. 逐步搭建一个强调自动化、便捷性、智能化与安全边界的 AI Payment 基础框架  
4. 在开源过程中不断验证哪些设计是真正可落地、可扩展、可审计的

它既是一次工程复盘，也是一条产品探索路线。

## 本地运行

安装依赖：

```bash
pnpm install
```

开发模式：

```bash
pnpm dev
```

命令行运行支付流 Demo：

```bash
pnpm cli
```

也可以带上一段自然语言请求直接运行：

```bash
pnpm cli 请帮我给供应商支付199元并完成结算
```

类型检查：

```bash
pnpm check
```

构建：

```bash
pnpm build
```

运行：

```bash
pnpm start
```

默认地址：

```text
http://localhost:3000
```

## Docker

构建镜像：

```bash
docker build -t claude-pay .
```

运行容器：

```bash
docker run --rm -p 3000:3000 claude-pay
```
